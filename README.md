# Xpl0it00ls

Открытый (не клон, а оригинальная реализация) менеджер iPhone на Python:
`pymobiledevice3` под капотом + два интерфейса на выбор —

- **TUI** (`Xpl0it00ls-TUI`) — терминальный интерфейс на [textual](https://github.com/Textualize/textual): ASCII-баннер, неоновая тёмная палитра (бирюзовый/маджента), рамки с подписями у каждой панели вывода, цветные статусы в логах. Основной интерфейс.
- **GUI** (`Xpl0it00ls`) — классическое окно на PySide6, попроще.

## Возможности

| Вкладка TUI | Что делает | Как реализовано |
|---|---|---|
| 📋 Обзор | Инфо об устройстве, батарея, перезагрузка | прямой Python API `pymobiledevice3.lockdown` |
| 📦 Приложения | Список / установка (.ipa) / удаление | `pymobiledevice3 apps list/install/uninstall` |
| 📁 Файлы | ls/pull/push/rm/mkdir по AFC (папка Media) | `pymobiledevice3 afc ...` |
| 📸 Экран | Скриншот экрана в PNG | `pymobiledevice3 developer (dvt) screenshot` |
| 🪵 Syslog | Живой системный лог с фильтром | `SyslogService(...).watch()`, с нормальной остановкой потока |
| 💾 Бэкап | Полный бэкап / восстановление | `pymobiledevice3 backup2 backup/restore` |
| ⚡ Прошивка | Обновление/восстановление по IPSW | `pymobiledevice3 restore update -i` |
| 🔓 Джейлбрейк | **Только детектор** checkra1n/palera1n в PATH + ссылки на офсайты | ничего не выполняет само |

### Почему нет «настоящего» джейлбрейка
Джейлбрейк — это эксплойты под конкретные версии iOS/чипов, которые быстро устаревают
и требуют отдельного, активно поддерживаемого проекта (checkra1n, palera1n). Встраивать
такой код в Xpl0it00ls было бы и небезопасно, и неправильно: вкладка «Джейлбрейк» только
проверяет, стоит ли у тебя уже один из этих инструментов, и даёт быстрый доступ к их
официальным сайтам — ставить и запускать их нужно отдельно, по их собственной инструкции.

### Про «прошивку»
`restore update` в pymobiledevice3 — это реальная операция перепрошивки устройства.
Она рискованная: при сбое, отключении кабеля или неподходящей прошивке телефон можно
привести в нерабочее состояние. Перед использованием — обязательно бэкап, стабильное
питание и кабель, не отключать устройство в процессе.

## Запуск из исходников

```bash
pip install -r requirements.txt
PYTHONPATH=src python run_tui.py     # терминальный интерфейс (рекомендуется)
PYTHONPATH=src python run.py         # классическое окно
```

## Без iTunes

- **Windows:** iTunes ставить не нужно, но без драйвера Apple (Apple Mobile Device
  Service) телефон по USB не будет виден вообще. Проще всего поставить «Apple Devices»
  из Microsoft Store. Сам драйвер легально нельзя вшить в наш exe, поэтому он ставится
  отдельно.
- **Linux:** `sudo apt install usbmuxd libimobiledevice-utils`.
- Для скриншотов/разработческих команд (`developer ...`) может понадобиться доверие
  компьютеру на экране телефона и, на новых iOS, включённый режим разработчика.
- Для «Прошивки» и работы в режиме DFU/Recovery нужен `libusb`.

## Сборка и релизы

`.github/workflows/build.yml` на каждый пуш тега `vX.Y.Z` собирает:

- `Xpl0it00ls.exe`, `Xpl0it00ls-TUI.exe` (Windows, PyInstaller `--onefile`)
- `Xpl0it00ls-x86_64.AppImage`, `Xpl0it00ls-TUI-x86_64.AppImage` (Linux)

и публикует их в GitHub Releases. Пуш в `main` без тега обновляет pre-release `nightly`.

```bash
git init && git add . && git commit -m "init"
git remote add origin https://github.com/<you>/xpl0it00ls.git
git push -u origin main
git tag v0.1.0 && git push --tags
```

## Важно, честно

Этот проект писался и проверялся без доступа в интернет и без подключённого iPhone
«на руках» у ассистента — синтаксис кода проверен, команды `pymobiledevice3` сверены
по актуальной (ноябрь 2026) документации, но живой прогон на реальном устройстве и в
CI может потребовать мелких правок (например, если у тебя версия `pymobiledevice3` с
чуть другими флагами — смотри `pymobiledevice3 <группа> --help`).
